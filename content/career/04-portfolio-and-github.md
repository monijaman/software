## Projects beat claims

"Knows Docker" on a resume is a claim. A deployed project with a `Dockerfile`, CI pipeline and a README is proof.

## What makes a strong project

| Weak | Strong |
| --- | --- |
| Todo app from a tutorial | Expense tracker with auth, roles, search and export |
| Runs only on your laptop | Deployed with a live link |
| No README | README with screenshot, architecture diagram, how to run |
| One giant commit | Small commits with clear messages |
| No tests | Some unit + integration tests in CI |

### Project ideas by role

- **Backend**: URL shortener with rate limiting and analytics; order service with a queue and idempotent payments.
- **Frontend**: dashboard with charts, filters, accessibility and Lighthouse score in the README.
- **Full stack**: booking app with real-time updates.
- **DevOps / Cloud**: deploy an app with Terraform on AWS, CI/CD, monitoring and a cost note.
- **AI**: document Q&A with RAG and an evaluation script.

## README template

```markdown
# Project Name
One sentence: what problem it solves.

Live demo · Screenshot · Video

## Features
## Architecture (diagram)
## Tech stack
## Run locally
## What I learned / trade-offs
```

## Make GitHub easy to scan

1. Pin your 3–6 best repos.
2. Add a profile README with a short intro and links.
3. Archive or make private old half-finished repos.
4. Contribute to open source, even docs fixes, to show collaboration.

## Personal site (optional)

A simple one-page site with About, Projects, Writing, and Contact is enough. Your custom domain on your resume looks professional.
